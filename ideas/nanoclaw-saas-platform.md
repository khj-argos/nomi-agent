# NanoClaw SaaS 플랫폼 — "나만의 AI를 키우는 플랫폼"

> 저장일: 2026-03-08 / 업데이트: 2026-03-08
> 상태: 아이디어 단계 (구현 미착수)  
> 연관 파일: 없음

---

## 핵심 컨셉

NanoClaw를 사용자별로 완전히 독립된 인스턴스로 제공하는 클라우드 플랫폼.
공유 인프라 없음 — 사용자마다 자신만의 NanoClaw가 생성되고, 사용할수록 나를 닮아가는 AI로 진화.

**한 줄 정의**: "쓸수록 나를 닮아가는 나만의 AI — 부르지 않아도 알아서 찾아오는 AI"

> 내부 개발 컨셉: 다마고치 — 성장하고 진화하는 나만의 에이전트 (브랜딩 아님)

---

## 핵심 원칙

| 원칙                | 내용                                                                  |
| ------------------- | --------------------------------------------------------------------- |
| **인프라만 제공**   | 우리는 NanoClaw가 돌아갈 서버/컨테이너 환경만 제공                    |
| **LLM은 사용자 것** | 기본: 사용자가 본인 Anthropic API 키 직접 입력                        |
| **LLM 옵션 제공**   | 옵션: 우리가 제공하는 LLM 사용 (추가 요금 or 번들)                    |
| **완전 격리**       | 사용자 간 데이터/컨테이너/메모리 완전 분리                            |
| **자동 진화**       | 대화 패턴, 습관, 선호도를 에이전트가 스스로 파악해 CLAUDE.md 업데이트 |
| **능동적 행동**     | 에이전트가 스스로 판단해서 먼저 말 걸어옴 — 사용자가 열지 않아도 동작 |

## LLM 전략

### Phase 1 — Claude 전용 (시작)

| 옵션 | 설명 | 사용자 비용 |
| ---- | ---- | --------- |
| **BYOK — Claude (기본)** | 사용자가 본인 Anthropic API 키 직접 입력 | API 사용량 직접 부담 + 플랫폼 구독료 |
| **우리 LLM — Ollama (옵션)** | 우리 서버에서 오픈소스 LLM 제공 (Llama, Mistral 등) | 플랫폼 구독료에 포함 or 추가 요금 |

**BYOK가 기본인 이유:**
- 우리는 인프라 비즈니스 — LLM 마진 리스크 없음
- 사용자가 비용 컨트롤 가능
- Anthropic 약관 준수 용이
- 사용자 신뢰도 높음 (내 키 = 내 데이터)

### Phase 2 — 멀티 LLM 지원 (확장)

| LLM | 방식 | 비고 |
| --- | ---- | ---- |
| Claude (Anthropic) | BYOK + 우리 제공 | Phase 1부터 지원 |
| GPT-4o (OpenAI) | BYOK | 사용자가 OpenAI API 키 입력 |
| Gemini (Google) | BYOK | 사용자가 Google API 키 입력 |
| 오픈소스 LLM | 우리 Ollama 서버 | Llama 3, Mistral, Qwen 등 |

**멀티 LLM 구현 방향:**
- 현재 NanoClaw는 `ANTHROPIC_BASE_URL` 환경변수 지원 — 호환 엔드포인트 교체 가능
- Phase 2에서 LLM 선택 UI 추가 + 엔드포인트 추상화 레이어 개발
- 사용자가 Web UI에서 원하는 LLM 선택 → 해당 API 키 입력 or 우리 제공 선택

### 우리가 제공하는 LLM — Ollama 기반

```
우리 인프라 (Ollama 서버)
  ├── Llama 3.x     ← 범용, 무료 제공 가능
  ├── Mistral       ← 경량, 빠른 응답
  ├── Qwen          ← 다국어 강점
  └── 기타 오픈소스 모델 (수시 업데이트)

→ 사용자는 API 키 없이도 사용 가능 (플랫폼 구독료만)
→ Claude 대비 성능 차이는 있지만 비용 부담 없음
→ 프라이버시 민감 사용자에게 어필 (외부 API 미사용)
```

## 능동적 행동 (Proactive AI)

기존 AI와의 근본적 차이.

```
기존 AI (ChatGPT, Claude):
  사용자가 열어야만 존재함
  → 열지 않으면 아무것도 안 함 (망각형 AI)

NanoClaw:
  에이전트가 스스로 판단해서 먼저 찾아옴
  → "오늘 주식 많이 빠졌네. 확인해봤어?"
  → "3일째 운동 기록이 없어. 괜찮아?"
  → "이번 주 마감 내일인데 진행 상황 어때?"
  (살아있는 AI — 나를 알아가는 AI)
```

**능동적 행동 트리거 — 에이전트가 스스로 판단:**
- 뉴스/시장 변화 감지 → 관련 알림
- 사용자 패턴 기반 → "평소 이 시간에 확인하시잖아요"
- 마감/일정 접근 → 선제적 리마인드
- 장기 미응답 → 안부 확인
- 학습된 관심사 → 관련 정보 푸시

## "나를 얼마나 아는가" — 성장/진화 표현 방식

레벨 숫자보다 **에이전트가 나를 얼마나 아는지**를 자연스럽게 느끼게 하는 방식.

```
Day 1:  "안녕하세요! 저는 아직 당신을 잘 몰라요 😊"
Day 7:  "커피 마실 때 집중이 잘 되시는 것 같더라고요"
Day 30: "이런 뉴스 좋아하시잖아요, 오늘 딱 맞는 거 찾았어요"
Day 90: 말 안 해도 알아서 챙겨주는 느낌
```

**진화 메커니즘:**

NanoClaw의 핵심 차별점 — 쓸수록 나를 닮아감.

```
사용자 대화/행동
      ↓
에이전트가 패턴 감지
  - 자주 쓰는 말투
  - 선호하는 답변 길이
  - 관심 있는 주제
  - 반복되는 업무 패턴
  - 능동적 행동에 대한 반응 (좋아함 / 싫어함)
      ↓
CLAUDE.md 자동 업데이트
  (사용자 승인 or 자동)
      ↓
다음 대화 + 능동적 행동에 반영
```
사용자 대화/행동
      ↓
에이전트가 패턴 감지
  - 자주 쓰는 말투
  - 선호하는 답변 길이
  - 관심 있는 주제
  - 반복되는 업무 패턴
      ↓
CLAUDE.md 자동 업데이트
  (사용자 승인 or 자동)
      ↓
다음 대화부터 반영
```

**예시 진화 시나리오:**

| 사용자 타입 | 진화 방향                                                   |
| ----------- | ----------------------------------------------------------- |
| 개발자      | 코드 리뷰 특화, GitHub 연동, 기술 스택 메모리               |
| 작가        | 글쓰기 스타일 학습, 창작 세계관 축적, 브런치 자동 포스팅    |
| 마케터      | SNS 트렌드 분석, 콘텐츠 스케줄링, 카피 스타일 학습          |
| 투자자      | 시장 리서치 패턴, 포트폴리오 추적, 뉴스 브리핑 커스터마이징 |

## 온보딩 Web UI — 3계층 설정 구조

일반 사용자는 CLAUDE.md를 몰라도 됨. UI가 자연어 → CLAUDE.md 변환을 담당.

### 계층 1 — 원클릭 템플릿 (일반 사용자)

```
"어떤 AI를 원하세요?"

  🧑‍💻 개발자 도우미       ✍️  글쓰기 파트너
  📈 마케팅 어시스턴트    💼  업무 비서
  📰 뉴스 브리퍼          🎯  나만의 설정 →
```

- 선택 즉시 해당 CLAUDE.md 템플릿 자동 생성
- 추가 질문 2~3개로 세부 조정 ("어떤 채널로 받을까요?" 등)
- 기술 지식 불필요 — 클릭만으로 완료

### 계층 2 — 자연어 입력 (중간 사용자)

```
"어떤 AI가 되었으면 해?"
→ [                                        ]
  "매일 아침 뉴스 브리핑 해주고,
   내 글쓰기 스타일 기억해줬으면 해"

→ AI가 이 텍스트를 CLAUDE.md로 자동 변환
→ 변환 결과 미리보기 → 사용자 확인 → 적용
```

- 자유 텍스트 입력
- LLM이 의도 파악 → CLAUDE.md 생성
- 생성된 설정 검토/수정 가능

### 계층 3 — 직접 편집 (고급 사용자 / 개발자)

```
CLAUDE.md 직접 편집 (코드 에디터 UI)
→ 완전한 자유도
→ 버전 히스토리 + 롤백 지원
```

### 설정 가능한 항목 전체

| 항목 | 계층 1 | 계층 2 | 계층 3 |
| ---- | ------ | ------ | ------ |
| 에이전트 이름/호칭 | ✅ | ✅ | ✅ |
| 에이전트 성격/말투 | ✅ (템플릿) | ✅ (자연어) | ✅ (직접) |
| 능동적 행동 주기 | ✅ | ✅ | ✅ |
| 관심 주제 설정 | ✅ | ✅ | ✅ |
| 채널 연결 | ✅ | ✅ | ✅ |
| 스케줄 설정 | ✅ (간단) | ✅ | ✅ |
| CLAUDE.md 직접 수정 | ❌ | ❌ | ✅ |
| 추가 디렉토리 마운트 | ❌ | ❌ | ✅ |

### 비용 효율화 전략

- **Idle 컨테이너 자동 중지**: 60분 비활성 시 컨테이너 중지 (CPU/RAM 0 사용)
- **요청 시 재시작**: 메시지 수신 시 컨테이너 자동 재시작 (수 초 내)
- **상태 보존**: 중지 중에도 SQLite + CLAUDE.md 유지 → 재시작 시 이전 맥락 그대로

### 온보딩 플로우 (핵심 — 이게 전부)

```

  → 이메일 or 소셜 로그인 (Google, GitHub)

Step 3: 에이전트 설정 — 3계층
  → 계층 1: 원클릭 템플릿
       🧑‍💻 개발자 도우미  ✍️ 글쓰기 파트너
       📈 마케팅 어시스턴트  💼 업무 비서
       📊 투자/금융 파트너   🎯 나만의 설정 →
  → 계층 2: 자연어 입력 ("어떤 AI가 되었으면 해?")
       입력 → LLM이 CLAUDE.md 자동 생성 → 미리보기 → 확인
  → 계층 3: 직접 편집 (고급 사용자 — 언제든 접근 가능)

Step 4: 채널 연결
  → WhatsApp:  QR코드 스캔 or 전화번호 페어링 코드
  → Telegram:  봇 토큰 입력 (봇 만드는 법 가이드 제공)
  → Slack:     워크스페이스 OAuth 연결
  → Discord:   봇 초대 링크
  (하나만 연결해도 완료, 나중에 추가 가능)

Step 5: 완료
  → 🎉 "[이름]님의 AI가 준비됐어요!"
  → "지금 [채널명]에서 메시지를 보내보세요"
  → 첫 메시지 예시 힌트 제공
```

## 보안 아키텍처

> SaaS 특성상 보안은 선택이 아닌 필수. 한 사용자의 데이터가 다른 사용자에게 노출되는 순간 서비스 종료.

### 기존 NanoClaw의 보안 강점 (이미 구현됨)

| 항목 | 구현 방식 |
| ---- | --------- |
| 컨테이너 격리 | 각 그룹 독립 Linux 컨테이너, non-root 실행 (uid 1000) |
| .env 차단 | `/dev/null`로 shadow mount — 에이전트가 API 키 직접 접근 불가 |
| Secrets stdin 전달 | API 키는 파일/마운트 아닌 stdin JSON으로만 주입 |
| 경로 차단 패턴 | `.ssh`, `.aws`, `.kube`, `credentials`, `id_rsa` 등 접근 불가 |
| Symlink traversal 방지 | 심볼릭 링크 해석 후 allowlist 재검증 |
| 세션 격리 | 그룹별 독립 `.claude/` 디렉토리 — 대화 이력 교차 접근 불가 |
| IPC 권한 분리 | main만 전체 관리, non-main은 본인 채팅/작업만 접근 |

### SaaS 확장 시 추가 필요한 보안

**1. API 키 암호화 저장**
```
사용자 입력 API 키
  → AES-256 암호화
  → 암호화 상태로 DB 저장
  → 컨테이너 시작 시만 복호화 → stdin 주입 → 즉시 메모리 해제
```

**2. 테넌트 간 네트워크 격리**
- 사용자 컨테이너 간 직접 통신 차단
- 외부 API 호출만 허용 (Egress 화이트리스트)
- 사용자 A의 컨테이너가 사용자 B의 데이터에 절대 접근 불가

**3. 프롬프트 인젝션 방어**
- 웹 크롤링 결과 → 에이전트 주입 전 살균 (OWASP LLM Top 1 취약점)
- MCP 도구 응답에 악성 프롬프트 삽입 가능성 차단
- 외부 입력과 시스템 프롬프트 구조적 분리

**4. 개인정보 보호 (GDPR/개인정보보호법)**
- 대화 데이터는 해당 사용자 인스턴스에만 저장
- 데이터 삭제 요청 시 완전 삭제 (인스턴스 + DB + 백업)
- 처리 목적 명시, 보존 기간 정책 수립
- EU 사용자 대상 시: 데이터 역외 이전 주의

**5. 감사 로깅**
- 모든 인스턴스 생성/삭제 기록
- API 키 접근 이벤트 기록
- 이상 트래픽 감지 (한 사용자가 비정상적으로 많은 요청)

## Skills / MCP 자동 제공 전략

> 일반 사용자는 Skills, MCP가 뭔지 모름. 우리가 알아서 제공해야 함.

### 개념

```
온보딩 설정 분석 (CLAUDE.md)
  → "이 사람 개발자네"
  → 개발자 Skills/MCP 자동 활성화
  → 사용자는 아무것도 몰라도 됨
```

### 직군별 자동 제공 패키지

| 직군 감지 기준 | 자동 제공 Skills/MCP |
| ------------- | ------------------- |
| **개발자** (GitHub, 코드, 배포 언급) | GitHub MCP, Linear/Jira MCP, 코드 리뷰 스킬, 음성 전사 |
| **작가/콘텐츠** (글쓰기, 브런치, SNS 언급) | WebSearch, 브런치 포스팅, 인스타 업로드, 문서 편집 |
| **마케터** (SNS, 광고, 트렌드 언급) | WebSearch, SNS 스케줄링, 트렌드 분석, 이메일 MCP |
| **투자자/금융** (주식, 코인, 포트폴리오 언급) | 금융 데이터 MCP, 뉴스 크롤링, 알림 스케줄러 |

## 검토 의견 — 심층 분석 (2026-03-08)

> 이 아이디어를 매우 깊게 고민한 후 정리한 실질적 평가와 제안.

### 1. 이 아이디어의 진짜 강점

**BYOK + 인프라만 제공 구조**가 기술적으로 가장 영리한 설계이다.
AI SaaS가 망하는 주는 이유 중 하나가 LLM 비용 구조 — 헤비 유저일수록 우리 손해가 커지는 구조.
는 이 모델은 그걸 원시 차단. **헤비 유저가 와도 우리 인프라 비용만 증가**하고 LLM 비용은 사용자 부담. 이건 진짜 영리한 설계다.

NanoClaw라는 **오픈소스 베이스**가 있다는 것도 큰 강점. 바닥부터 짓는 게 아니라
검증된 구조 위에 Control Plane과 UI만 어듀면 되니까 — MVP까지 가는 경로가 다른 AI 스타트업보다 훨씬 짧다.

### 2. 가장 우려되는 부분 — 온보딩 허들

**Step 2 (API 키 입력)가 최대 병목이다.**

| 대상 | 소요 시간 |
| ---- | --------- |
| 개발자 | 2분 (이미 알고 있음) |
| 일반 사용자 | 10~20분 (영문 UI, 신용카드 등록, 결제 정보...) |

�결책: **우리 LLM (Ollama) 플랜을 기본값으로 올려야 한다.**
API 키 입력은 “고급 옵션”으로 내리고, 처음엔 우리 LLM으로 바로 시작하게 하는 게 이탈률을 낙춤다.
수익 구조상으로도 Ollama 플랜이 더 안정적인 수익원이 될 수 있다.

### 3. 과소평가된 부분 — 능동적 행동 엔진

능동적 행동이 이 서비스의 **핵심 차별점**이지만, 동시에 **생사를 가르는 리스크**다.

```
너무 자주 말 걸면  → 스팬, 알림 꺼고 싶어집 (이탈)
너무 안 말 걸면  → 기존 AI랑 차이 없음 (이탈)
타이밍이 안 맞으면 → 짜증남, 신뢰 파괴 (이탈)
```

권장: 시작은 **매우 보수적**으로. 사용자가 먼저 패턴을 쌓게 하고, 신뢰가 생긴 후에 능동성을 높이는 방식.
“알림 좋았어요/싫어요” 피드백 루프가 없으면 능동적 행동은 참사가 뤎어.

### 4. 경쟁 포지셔닝

ChatGPT/Claude.ai와 직접 경쟁하면 진다. **다른 카테고리**로 포지셔닝해야 한다.

```
ChatGPT / Claude.ai:  “질문하면 답해주는 AI”  (도구)
NanoClaw SaaS:         “나를 위해 일하는 AI 직원”  (존재)
```

마케팅 메시지: **“더 나은 ChatGPT”가 아니라 “AI 직원 고용”**으로 잡아야 한다.

### 5. 놓친 설계 — 쳋 주 경험

**온보딩 이후 첫 주 시퀀스가 리텐션을 결정한다.**

```
Day 0 (온보딩 완료):
  AI: "안녕하세요! 저 [AI 이름]이에요. 지금부터 열심히 해볼게요 😊"

Day 1:
  AI: "어제 첫 대화 했는데, 저한테 가장 많이 부탁하고 싶은 게 뮤에요?"

Day 3:
  AI: "관심사가 [XX]인 것 같더라고요.
       매일 아침 [관련 정보] 보내드릴까요?"

Day 7:
  AI: "일주일 됨는데! 제가 이런 걸 파악했어요: [요약]
       맞게 이해한 건가요?"
```

이 **쳋 주 시퀀스**가 리텐션을 결정한다. 여기서 “이 AI 나를 알아가고 있구나”를 느끼면 이탈률이 몿 떨어진다.
**TRD 단계에서 쳍 주 시퀀스 설계를 반드시 포함할 것.**

### 6. 수익 모델 보완

**Ollama 기반 우리 LLM 플랜이 수익의 핵심이 될 수 있다.**

```
BYOK 플랜:
  우리 수익 = 구독료 - 서버 인프라 비용
  LLM 비용은 사용자 부담 → 마진 리스크 없음

우리 LLM (Ollama) 플랜:
  우리 수익 = 구독료 - (서버 + GPU/CPU 비용)
  오픈소스 모델이라 구독료이 충분하면 권늹 투자 후 높은 마진 가능
```

**결론**: Ollama 플랜을 잘 설계하면 BYOK보다 수익성이 높은 플랜이 된다.
이 플랜으로 진입 장벽을 낙춰(API 키 불필요) + 수익도 높이는 Two-for-one 전략 가능.
